The problem

Apps carry code from companies you never chose.

Analytics, advertising, attribution, session-replay and crash-reporting SDKs sit inside the apps you use. Each one is a channel from an app to a company you may never have heard of, and nothing on your computer lists them.

Privacy labels are written by the publisher. Online scanners want the app uploaded. exposure reads the app itself, on your machine, and shows you where it looked.

What exposure does

It names the company, and shows the bytes that prove it.

exposure reads the apps on your Mac and the Android packages you give it, finds the analytics, advertising, attribution, session-replay and crash-reporting SDKs they ship, and names the company behind each one. Every finding has a grade and cites its raw records: the marker, the file, how many times.

A real scan

One Mac, sixteen apps, 2.2 seconds.

The maintainer's Mac, scanned on 22 November 2026 with exposure 0.1.0: 16 apps and 8 browser extensions, 10,756 files and 6.8 GB, with the cache off. Nothing left the machine. These are the companies it named, and in how many apps.

App names are left out on purpose: the list of apps a person uses is sensitive in itself, which is why a report stays on your machine. The same scan also listed updater components (Squirrel in 6 apps, Sparkle in 5), which name no company, and 117 claims about what the apps and extensions may access.

How it works

Three steps, and none of them runs the app.

No guessing from names, and no lookup in anyone's cloud. A finding exists only when the app's own files hold a marker that an SDK cannot avoid leaving.

  • It reads the files, and only reads them.

    Mach-O binaries, Info.plist and privacy manifests on macOS; app.asar archives in Electron apps; DEX code and the manifest in Android packages; each browser extension's manifest.json. It never runs anything it scans, changes anything, or follows a symbolic link inside an app.

  • It matches 48 signed rules.

    A rule lists literal markers an SDK cannot avoid leaving: a class name, a framework folder, an endpoint. Each marker has a boundary rule and cites the SDK's own code or documentation. Rules are data, with no regular expressions and no scripts, and the scanner loads only a rule pack whose signature checks out.

  • It writes a report you can check by hand.

    One HTML page grouped by company, and a JSON file for programs. The page loads nothing and runs no script, whatever the scanned apps' names contain.

Every finding is graded

Graded facts, and never a score.

The grade says what kind of evidence there is, and a finding takes the highest grade its evidence reaches. No finding says what an app or a company intends.

The headline counts companies in five categories: advertising, analytics, attribution, profiling and session replay. Crash reporting, push messaging, payments and update feeds are listed under the company that runs them, and not counted. A crash report can still carry data about you, so the report shows every one.

Trust and privacy

Safer than the apps it reports on.

A tool that reads the list of apps you use has to be. These are mechanisms, checked in CI, not promises.

  • No network code

    Nothing leaves the machine, because nothing in it can send. Socket-capable dependencies are banned, and CI proves that a scan opens no socket.

    dependency banssymbol audit of the binarya network namespace with no interfacesstracea macOS sandbox that denies the network

  • Read only

    Files are opened for reading. Nothing is extracted to disk and nothing scanned is run. Of a browser profile, only each extension's manifest is read: never your history, cookies, bookmarks or logins.

  • Two files, both private

    A scan writes the report and a results cache, both readable only by you. --no-cache turns the cache off, and you can delete it at any time.

  • The report is inert

    It runs no script and loads nothing from anywhere. It holds no date, no device name and no path you gave it.

  • Same input, same bytes

    The same apps and rule pack give a byte-identical report on any machine, at any thread count. Two clean builds of one commit give the same binary, and CI checks it nightly.

  • Open source

    The code is Apache-2.0. The rules and company map are CC BY 4.0, and every marker cites the vendor's own code or documentation.

What a scan cannot see, and every report says so: what happens on a company's servers, what is inside encrypted traffic, tracking routed through an app's own domain, SDKs it has no rule for, and whether shipped code ever runs. A clean report does not mean a clean app. Read the threat model.

Who it is for

For people who ship apps, use them, and write about them.

  • Teams that ship apps

    Know which third-party SDKs your release actually contains, from the build itself, before it goes out. Scan an .apk or a Mac app on a machine you control and keep the JSON evidence with your privacy review. Your build never leaves your machine.

    Next release a diff between two buildsa release gate in CI.aab bundles

    Planned a GitHub Action

  • People who want to know

    One command lists the companies whose code ships in your Mac's apps, and the powerful permissions your browser extensions hold. Then it tells you what you can do: an app's own opt-out where one is documented, the hosts to block with a firewall such as LuLu or Little Snitch, the System Settings pane for each permission. You decide; exposure changes nothing.

  • Researchers and journalists

    A contains finding depends only on the app file and the rule pack, so anyone holding the same file gets the same records. Cite the file's SHA-256 and the record, and your readers can check it. A wrong finding is settled by the files, in a public dispute.

Get started

Install it, then run one command.

exposure is one command-line binary for macOS on Apple silicon and Linux. It is built from source on your machine, so you can read the code it runs.

From source Works today

Apple's command-line tools, Rust 1.97 or later, then one cargo install. On Linux, skip the first line.

$ xcode-select --install
$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
$ cargo install --git https://github.com/Adityaakr/exposure-scanner --locked --tag v0.1.0 exposure

Homebrew Next release

From the repository's own tap, building from source.

$ brew tap Adityaakr/exposure-scanner https://github.com/Adityaakr/exposure-scanner
$ brew install adityaakr/exposure-scanner/exposure

Not available yet. The formula is merged and ships with the next release; until then, install from source above.

Then scan

On a Mac this reads /Applications, ~/Applications and your browser extensions, writes the report to a folder only you can read, prints what needs your attention first, and opens the report.

$ exposure scan

To scan one app or an Android package, name it: exposure scan Some.app app-release.apk. For a program, --json - prints the JSON report.

Questions

The things people ask first.

Does it send anything anywhere?

No. It contains no network code, and CI proves that a scan opens no socket.

If an app "ships" an SDK, does it send my data to that company?

Not necessarily. "Ships" means the code is in the app's files. The app may never call it, or may call it only for some users. Showing a live connection is a later milestone.

Why is crash reporting not in the headline count?

The headline counts five categories: advertising, analytics, attribution, profiling and session replay. Crash reporting, push messaging and payments are listed in the report under the company that runs them, but they are not counted. A crash report can still carry data about you, so the report shows every one.

How accurate is it?
  • Every marker of every rule is planted in a synthetic app and must be found: 231 of 231 today.
  • Thirty real apps that ship no third-party SDK, including ad blockers and a browser built on Chromium, must come back with no third-party finding, and they do.
  • It knows 48 SDKs. An SDK it has no rule for is not reported.
Does it work on my iPhone?

No. iOS does not let one app read another's files. Planned Import the App Privacy Report your iPhone can export.

And my Android phone?

It scans .apk files on a Mac or a Linux machine. Next release Android App Bundles (.aab) too. Planned Pull the apps from a phone connected over USB.

Windows?

Not planned yet.

An app of mine is named, and the finding is wrong.

Use the dispute form. A dispute is settled by the files: the build is fetched again from its public address, and every record is checked against its bytes. How disputes work.

Why build from source?

A scanner that reads the list of your apps is more credible when you can build it yourself and get the same binary. The Homebrew formula, which ships with the next release, builds from source too.

Is it free?

Yes. The scanner is free and open source under Apache-2.0, and its rules are CC BY 4.0.

Run it on one app you use every day.

$ exposure scan /Applications/YourApp.app
