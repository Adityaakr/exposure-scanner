See whose code is inside your apps.

exposure reads the apps on your Mac and the Android packages you give it, finds the analytics, advertising, attribution, session-replay and crash-reporting SDKs they ship, and names the company behind each one. Every finding points to the file and the bytes that prove it.

It runs on your machine, and it has no network code at all.

How it works

It reads the files, matches signed rules, and shows its work.

No guessing from names, no cloud lookup. A finding exists only when the app's own files hold a marker that an SDK cannot avoid leaving.

  1. INApps on diskMac apps, Electron apps, .apk files, browser extensions
  2. 01CollectorsRead only, in bounded windows; nothing runs
  3. 02MatchersLiteral markers from 48 signed rules
  4. 03EvidenceRecords keyed by SHA-256
  5. 04ClaimsCompany, party and grade
  6. OUTReportHTML for you, JSON for programs
1

It reads the files, and only reads them.

  • Mach-O binaries, Info.plist and privacy manifests on macOS
  • app.asar archives in Electron apps
  • DEX code and the manifest in Android packages
  • Each browser extension's manifest.json

It never runs anything it scans, changes anything, extracts to disk, or follows a symbolic link inside an app.

2

It matches 48 signed rules.

A rule lists literal markers an SDK cannot avoid leaving: a class name, a framework folder, an endpoint. Each marker has a boundary rule and cites the SDK's own code or documentation.

Rules are data: no regular expressions, no scripts. The scanner loads only a rule pack whose signature checks out.

3

It writes a report you can check by hand.

One HTML page grouped by company, and a JSON file for programs. Every finding has a grade and cites its raw records: the marker, the file, how many times.

The page loads nothing and runs no script, whatever the scanned apps' names contain.

Every finding is a graded fact.

The grade says what kind of evidence there is. A finding takes the highest grade its evidence reaches, and no finding says what an app or a company intends.

There is no score. The headline counts companies in five categories:

  • Advertising
  • Analytics
  • Attribution
  • Profiling
  • Session replay

Crash reporting, push messaging, payments and update feeds are listed under the company that runs them, and not counted.

  • declaresThe app's own files name this endpoint, such as an update feed or a domain in its privacy manifest.An address, not an observed connection.Today
  • containsThe app ships this code: a class, package, framework or endpoint literal.In a word, "ships". Present, not proof that it runs.Today
  • contactsThe operating system or a capture recorded a connection to the company.In a word, "contacted".Planned
  • confirmedThe receiver's own records list the app as a sender, or a payload was inspected.Planned

Who it is for

One binary, read the same way by everyone who needs the answer.

Teams that ship apps

Know which third-party SDKs your release actually contains, from the build itself, before it goes out.

  • Scan an .apk or a Mac app on a machine you control
  • Keep the JSON evidence with your privacy review
  • Your build never leaves your machine

Planned for teams

  • A diff between two builds and a release gate in CI
  • A GitHub Action that comments the difference on the pull request
  • .aab bundles, and checks against your privacy manifest and Data Safety answers

People who want to know

One command lists the companies whose code ships in your Mac's apps, and the powerful permissions your browser extensions hold.

  • Then it tells you what you can do: an app's own opt-out where one is documented
  • The hosts to block with a firewall such as LuLu or Little Snitch
  • The System Settings pane for each permission

You decide. exposure changes nothing.

Researchers and journalists

A contains finding depends only on the app file and the rule pack, so anyone holding the same file gets the same records.

  • Cite the file's SHA-256 and the record id
  • Every marker cites the vendor's own code or documentation
  • Wrong finding? A public dispute is settled by the files

Your readers can check it by hand.

Trust and privacy

A tool that reads your app list has to be safer than the apps it reports on.

These are mechanisms checked in CI, not promises.

No network code

Nothing leaves the machine, because nothing in it can send.

Socket-capable dependencies are banned. CI checks the binary imports no socket function, and runs a scan with no network interfaces, under strace, and in a macOS sandbox that denies the network.

Read only

Files are opened for reading. Nothing is extracted to disk, and nothing scanned is run.

Of a browser profile, only each extension's manifest is read: never your history, cookies, bookmarks or logins.

Two files, both private

A scan writes the report and a results cache, both readable only by you.

--no-cache turns the cache off, and you can delete it at any time.

The report is inert

It runs no script and loads nothing from anywhere.

It holds no date, no device name and no path you gave it.

Same input, same bytes

The same apps and rule pack give a byte-identical report on any machine, at any thread count.

Two clean builds of one commit give the same binary; CI checks it nightly.

Open source

The code is Apache-2.0. The rules and company map are CC BY 4.0.

Every marker cites the vendor's own code or documentation. Read the threat model.

What it cannot see

Every report says so too.

  • What happens on a company's servers
  • What is inside encrypted traffic
  • Tracking routed through an app's own domain
  • SDKs it has no rule for
  • Whether shipped code ever runs
  • Which permissions you granted in System Settings
  • A clean report does not mean a clean app.

Get started

Install it, then run one command.

Homebrew

Planned

One command from the repository's own tap. The formula builds exposure from source on your Mac.

$ brew tap Adityaakr/exposure-scanner https://github.com/Adityaakr/exposure-scanner
$ brew install exposure

This lands with the CLI v1 release, which adds the formula. Until then, build from source.

From source

Works today

Apple's command-line tools, Rust 1.97 or later, then one cargo install. On Linux, skip the first line.

$ xcode-select --install
$ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
$ cargo install --git https://github.com/Adityaakr/exposure-scanner --locked --tag v0.1.0 exposure

The build takes a minute or two and puts exposure in ~/.cargo/bin. More install options.

Then run it

On a Mac, exposure scan reads /Applications, ~/Applications and your browser extensions. It writes the report to a folder only you can read, prints what to do first, and opens the report.

  • Scan this Mac

    $ exposure scan

  • Scan one app or an Android package, and nothing else

    $ exposure scan /Applications/Some.app app-release.apk

  • Give a program the JSON report

    $ exposure scan app-release.apk --json -

Questions

Straight answers.

Something missing? Ask on GitHub.

Does it send anything anywhere?

No. It contains no network code, and CI proves that a scan opens no socket.

If an app "ships" an SDK, does it send my data to that company?

Not necessarily. "Ships" means the code is in the app's files. The app may never call it, or may call it only for some users. Showing a live connection is a later milestone.

Why is crash reporting not in the headline count?

The headline counts five categories: advertising, analytics, attribution, profiling and session replay. Crash reporting, push messaging and payments are listed in the report under the company that runs them, but they are not counted. A crash report can still carry data about you, so the report shows every one.

How accurate is it?
  • Every marker of every rule is planted in a synthetic app and must be found: 231 of 231 today.
  • Thirty real apps that ship no third-party SDK, including ad blockers and a browser built on Chromium, must come back with no third-party finding, and they do.
  • It knows 48 SDKs. An SDK it has no rule for is not reported.
Does it work on my iPhone?

No. iOS does not let one app read another's files. Planned Import the App Privacy Report your iPhone can export.

And my Android phone?

It scans .apk files on a Mac or a Linux machine. Planned Pull the apps from a phone connected over USB.

Windows?

Not planned yet.

An app of mine is named, and the finding is wrong.

Use the dispute form. A dispute is settled by the files: the build is fetched again from its public address, and every record is checked against its bytes. How disputes work.

Why build from source?

A scanner that reads the list of your apps is more credible when you can build it yourself and get the same binary. The planned Homebrew formula builds from source too, in one command.

Is it free?

Yes. The scanner is free and open source under Apache-2.0, and its rules are CC BY 4.0.
