Install

exposure is one command-line binary. It is built from source on your machine, so you can read the code it runs.

From source Works today

On a Mac with Apple silicon, or on Linux:

  1. Install Apple's command-line tools, which hold the linker and git. Skip this on Linux.

    $ xcode-select --install

  2. Install Rust 1.97 or later with rustup.

    $ curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
$ source "$HOME/.cargo/env"

    If Rust is already installed, rustup update stable brings it up to date.

  3. Install exposure.

    $ cargo install --git https://github.com/Adityaakr/exposure-scanner --locked --tag v0.1.0 exposure

    --locked builds with the exact dependency versions the project tests. The build takes a minute or two and puts exposure in ~/.cargo/bin. Leave out --tag v0.1.0 to install the latest commit instead of the release.

Homebrew Next release

The repository is its own Homebrew tap, with a formula that builds from source:

$ brew tap Adityaakr/exposure-scanner https://github.com/Adityaakr/exposure-scanner
$ brew install adityaakr/exposure-scanner/exposure

Not available yet. The formula is merged and ships with the next release; until then, install from source above.

From a clone

The clone's rust-toolchain.toml pins the exact toolchain.

$ git clone https://github.com/Adityaakr/exposure-scanner.git
$ cd exposure-scanner
$ cargo build --release --package exposure
# the binary is target/release/exposure

Your first scan

$ exposure scan

That is all. On macOS it reads the apps in /Applications and ~/Applications and the extensions in your browser profiles. It writes the report to a folder only you can read, opens it in your browser, and prints what needs your attention first. Apple's own apps in /System/Applications are not scanned unless you name that folder.

To scan something else, name it. When you name any path, only what you name is scanned:

$ exposure scan /Applications/Some.app app-release.apk

This is what a scan of two of the repository's test apps prints:

$ exposure scan android/Skeleton.apk macos/ElectronSkeleton.app
…
Your report: /Users/you/Library/Application Support/exposure/report.html
It is open in your browser.

Scanned 2 apps.

What needs your attention first (1 of 2 things you can do):

  1. [High] PostHog
       Analytics by PostHog Inc., in ElectronSkeleton and Skeleton.
       Block app.posthog.com, eu.i.posthog.com, i.posthog.com and
       us.i.posthog.com with an outbound firewall such as LuLu (free) or Little
       Snitch.

1 more entry in the report, under What you can do.

The headline counts:
  1 company whose code the scanned apps ship, in advertising, analytics and the like
  2 apps with code or an endpoint of a company other than their publisher
  …

Nothing is sent anywhere and nothing on your Mac is changed: the report says what you can do, and you decide. See the whole report.

Commands and options

exposure scan [PATH...] [--html FILE] [--json FILE] [--no-open] [--threads N] [--no-cache]
exposure report FILE [--html FILE] [--json FILE]
exposure rules show
exposure rules verify PACK --sig SIGNATURE
exposure --help | --version
CommandWhat it does
scanScans apps, extensions, or folders of them, and writes the report.
reportDerives the report again from a saved JSON report.
rules showLists the built-in rule pack.
rules verifyChecks a signed rule pack file, offline.
OptionEffect
PATHA macOS .app bundle, an Android .apk file, a browser extension (a Firefox .xpi file, or a Chromium <id>/<version> folder), or a folder searched for all of them, never inside a bundle.
--html FILEWrite the report for reading: one self-contained page, grouped by company.
--json FILEWrite the report a program reads, which exposure report can render again. A FILE of - is standard output.
--no-openDo not open the report in the browser.
--threads NWorker threads. Default: one per core. The report does not depend on it.
--no-cacheRead every app again, and neither use nor keep the results cache.

For scripts, exposure scan app-release.apk --json - prints the JSON report on standard output. A summary goes to standard error, ending with a scope line that says where the scan looked; it names no app and no path.

A path that does not exist is refused before anything is read. After that, an app that cannot be read never stops the scan: it is reported as a coverage note, never as "nothing found". In 0.1.0 a scan that completes exits with status 0, whatever it finds. Next release --fail-on exits with status 3 when a finding meets a condition, such as a company or a category, and exposure diff OLD NEW compares two JSON reports.

Where files go

A scan writes two things, both readable by their owner only, in folders only the owner can open.

FilemacOSElsewhere
The report, when you give neither --html nor --json~/Library/Application Support/exposure/report.html$XDG_DATA_HOME/exposure, else ~/.local/share/exposure
The results cache~/Library/Caches/exposure$XDG_CACHE_HOME/exposure, else ~/.cache/exposure

Each scan replaces the report of the one before. The cache keeps what was found in each app, so an app that has not changed is not read again; the report is the same with the cache and without it, byte for byte. The cache holds no paths and no file lists, can be deleted at any time, and is not used by a scan run as root.

Reading the report

Every finding is a claim with a grade. A claim takes the highest grade its evidence supports, and cites the raw records it rests on: the marker, the file, the table, how often.

GradeIn a wordMeansStatus
declaresdeclaresThe app's own files name the endpoint, such as an update feed or a tracking domain in a privacy manifest.Today
containsshipsThe app ships the SDK's code: a class, package, framework or endpoint literal.Today
contactscontactedThe operating system or a capture recorded a connection.Planned
confirmedconfirmedThe receiver lists the sender, or a payload was inspected.Planned

contains proves presence, not use. An app can ship code it never calls, or code of a service that has been retired.

What an app may access has its own ladder: requested means the app asks for it. The two ladders are never joined: "ships an analytics SDK" and "may access the camera" never become "sends pictures to an analytics company".

The headline: three counts, and no score

  • Companies at contacts or above (none yet, since a scan reads files only)
  • Companies at contains
  • Apps with at least one third-party channel

Only claims that name a company in five categories count: advertising, analytics, attribution, profiling and session replay. Crash reporting, push delivery, payments, customer messaging, update feeds, components and every access claim are listed in the report but not counted. Each claim in the JSON says whether it counts, so the numbers can be recounted.

What you can do

The report opens with what needs your attention: the few checklist entries that matter most, each with its first step. The whole checklist follows, and each finding has its own steps: an app's own opt-out where its publisher documents one; hosts to block with an outbound firewall such as LuLu or Little Snitch, for the counted categories; the System Settings pane, or the Android Settings page, of each permission; and how to narrow or remove a browser extension. The scanner applies none of it.

What a scan reads

InputWhat is read
macOS appsFramework folders, linked libraries, Objective-C class names and literals in Mach-O binaries; Info.plist; privacy manifests; usage descriptions and entitlements.
Electron appsThe app.asar archive: npm packages in its file table, and literals in the app's own scripts.
Android packagesThe binary manifest, and classes and strings in the DEX files.
Browser extensionsEach extension's manifest.json, and its message catalogue when its name refers to one. Chrome, Edge, Brave, Arc, Dia, Vivaldi, Chromium and Firefox profiles.

Never read: your browsing history, cookies, bookmarks, saved logins or pages. Nothing is extracted to disk, nothing scanned is run, and symbolic links inside an app are never followed. The one process exposure starts is macOS's opener, for the report it has just written, after a scan in a terminal, unless you pass --no-open.

Verify a build

Two clean builds of one commit give the same binary, byte for byte. From a clone, this exports the commit twice to two folders, builds each in release mode, and compares the two binaries. CI runs it nightly on macOS and Linux.

$ cargo xtask repro

A build on another machine gives the same bytes with the same toolchain, target and cargo home folder.

Uninstall

Remove the binary, then the report and the cache if you want them gone too (macOS paths shown):

$ cargo uninstall exposure
$ rm -rf ~/Library/Caches/exposure "$HOME/Library/Application Support/exposure"

Help and disputes

  • A false positive, or an SDK the scanner misses: open an issue. These are the most useful reports.
  • Your app or company is named and you believe a finding is wrong: use the dispute form. How a dispute is settled.
